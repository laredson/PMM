PalModMerger v1 preview 28
==========================

Core conflict contract
----------------------
A shared file is NOT a winner-takes-all conflict. PMM resolves at the smallest
proven value/property unit:

1. Compare every provider against Vanilla/current semantic state.
2. Merge every independent change automatically, even when those changes live
   in the same cooked asset.
3. Only when two or more providers request different values for the same proven
   property/byte does PMM create a True Conflict row.
4. That row offers the competing providers and, where the encoder can prove it
   safe, Vanilla and Custom.
5. After that single value is resolved, all independent changes from the same
   file are still composed into the final cooked asset.

Reference example: MultiJump Triple and Quad request different values in the
same structural field of BP_PlayerBase. The user chooses Triple/Quad/Vanilla/
Custom for that field; FlyMode's separate BP_PlayerBase edits are then merged
onto the selected state. PMM never asks the user to choose Fly OR MultiJump as a
whole-file winner.

Merge changes
-------------
- StaticItem fixed-size IntPropertyData/Int32 transfer. This removes the
  WaterBuildKit.Rank blocker from the uploaded Early Aquatic fixture.
- StaticItem stale-provider ambiguities can now become value-level true
  conflicts instead of whole-asset Unsupported when the property is safely
  encodable.
- RelocatableDelta-v2 recognizes same-structure anchor variants and surfaces
  differing bytes as true conflicts instead of Unsupported.
- Binary, DataTable, StaticItem and proven Relocatable conflict rows support
  provider choices; Vanilla/Custom are offered when the adapter can encode them
  safely.
- Patch manifests record DecisionSignature so changing a true-conflict choice
  invalidates an older local patch.

Library / deployment changes
----------------------------
- Import only changes the PMM library.
- Source mods can be Disable/backed-up or deleted locally.
- Build produces a local compatibility overlay only.
- DEPLOY explicitly synchronizes active source PAKs + current overlay to
  Palworld ~mods and applies managed removals.
- Exact duplicate PAKs and proven quasi-duplicate alternatives can be omitted
  from deployment without deleting their library copies.
- PMM patches remain backed up under Builds\Current and never become source
  providers.

UI changes
----------
- Persistent green Analyze completion state until active source inputs change.
- True-conflict panel describes competing mods for the parameter while noting
  other same-file providers that will still be merged automatically.
- Provider / Vanilla / Custom resolution workflow with editable Custom value.
- Dedicated green DEPLOY button.
- Disable / backup and Delete from library buttons under the source mod list.

Captured fixture expectations
-----------------------------
With the uploaded test set containing Early Aquatic + MultiJump Triple +
MultiJump Quad, the intended Analyze result is:

  Shared: 4 | merged automatically: 3 | true-conflict decisions: 1 |
  unsupported: 0 | identical: 0

The one decision is Triple vs Quad inside BP_PlayerBase. FlyMode is not a
competitor in that row because it changes different parts of BP_PlayerBase.
