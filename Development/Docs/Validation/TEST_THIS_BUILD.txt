QA2 professional hardening regression
=====================================

12) Large Unsupported set / disk behavior:
    Analyze a set with many conflicts (PalVariety-style is ideal). During Analyze, Cache\Analyze_* may
    exist, but each asset scratch is reclaimed as soon as that asset finishes. At Analyze completion,
    Cache\Analyze_* must be gone. Data\Review must remain metadata-only.

13) Missing/corrupt review metadata:
    After Analyze, temporarily rename one Unsupported case.json and try CREATE AI HANDOFF.
    Expected: AIIO refuses the bundle and tells you to Analyze again. It must not silently omit that case.

14) Stale source protection:
    After Analyze, replace/change one active source PAK, then try CREATE AI HANDOFF or Build.
    Expected: PMM refuses the stale plan. Restore the PAK and Analyze again.

15) Palworld update protection:
    After Analyze, change the Vanilla PAK set (or test after a real game update).
    Expected: the old plan/saved patch is stale and PMM requires a new Analyze/Build.

16) One bundle / exact sources:
    CREATE AI HANDOFF must produce one combined ZIP containing every current Unsupported case,
    including plain/non-Unreal Unsupported files. Verify the ZIP contains no *.pak entry.

17) Provider-name collision:
    Include a source mod named Vanilla.pak if available.
    Expected: installed game files remain under sources\Vanilla and the mod uses a different provider folder.

18) Low-disk / size gates:
    AIIO must stop before staging if its conservative working-space requirement exceeds free space.
    >5 GiB raw input or an actual ZIP >512 MiB requires explicit user approval. Cancel leaves no stage/.partial.

19) Cross-process lock:
    Open two PMM instances and start Analyze/Build/AI handoff concurrently.
    Expected: only one background Analyze/Build/AIHandoff operation owns the installation at a time;
    the second attempt fails cleanly instead of racing merge-plan/Review/staging.

20) Hard-kill hygiene:
    Kill PMM during Analyze, AIIO, Build, Import, manual-solution validation or Game Reference refresh.
    Restart PMM. Expected: only abandoned PMM-owned transient stages are removed/recovered; user data,
    valid handoffs, mods, saves, Knowledge and current Game Reference remain intact.

21) Unsafe/corrupt returned ZIP:
    A truncated ZIP, ../ or ..\\ path, ADS-style name (file:stream), Windows device name (CON/NUL/COM1/LPT1),
    symlink entry, case-colliding duplicate path or returned solution expanding beyond 5 GiB must be rejected.

22) Save backup/restore regression:
    Create a backup, restore it, and verify Level.sav. Restore now fully extracts/validates to staging before
    touching the live world, performs a safety backup first, and attempts rollback if the live copy fails.

23) Knowledge contribution regression:
    Create a tested Knowledge contribution for a validated manual solution.
    Expected: native PMMRuntime archive creation succeeds and no PowerShell Compress-Archive path is used.
